# 기능적·비기능적 요구사항 명세 v2.0 (FR / NFR)

> **작성 원칙 (교수님 4차 피드백 1·3·4번 + v2.0 정산 정책 잠금 반영):**
> 1. 실제 UI 화면(현행 + Taximate 3.0 목표)과 API를 기준으로 **모든 활성 기능을 누락 없이** 정의한다.
> 2. **1항목 = 1기능 = 1줄** 원칙을 지킨다.
> 3. **MVP 우선순위(`P0 / P1 / P2`)** 를 명확히 구분하고, 시연 전용 기능은 **`Demo`** 로 격리한다.
> 4. 수치 조건(15분·10%·6자리·6시간·24시간)과 내부 구현(스케줄러·DB·해시)은 업무 규칙·설계 문서로 분리한다.
