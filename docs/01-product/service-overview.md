# 캠퍼스 택시메이트 — 서비스 기준 명세 (v2.0)

> **문서 상태:** 현행 `main` 구현·검증 반영 (2026-11-27)
> **문서 목적:** 서비스 정의·범위·업무 규칙·우선순위를 하나로 통일해 요구사항, 설계, 구현, 검증이 동일한 기준을 따르도록 한다.
> *(현행 저장소 `main`은 3계층 후불 1회 결제 정산(`flow-version=3`) 및 Deep Green UI 리뉴얼 전환이 완료된 상태다.)*

---

## 1. 서비스 한 문장 정의

> **캠퍼스 택시메이트(Taximate)** 는 이동 방향과 출발 시간이 비슷한 대학생을 **자동으로 매칭**하고, 각자의 **단독 예상 요금 비율에 따라 실제 택시요금을 분담**하며, **탑승 전 결제 없이 이용 후 실제 부담금만 1회 결제**하는 통학 동승 웹 서비스다.

### 핵심 가치 3가지 (차별점)
1. **조건 기반 자동 매칭**: 게시글로 일행을 직접 구하지 않고, 요청 1회로 지연(≤ 15분)·절약(≥ 10%)·동성 조건을 검증한 같은 승차 지점 일행(2~4명)을 자동 구성한다.
2. **단독 예상 요금 비율 분담**: `1/N`의 근거리 하차자 불이익을 없애고, 실제 택시요금을 각자의 단독 예상 요금 비율로 1원 단위까지 공정하게 나눈다.
3. **투명한 후불 1회 결제**: 적립금·보험 구조나 매번 일어나는 선결제 부분환불 없이, **결제수단 사전 등록 → 운행 후 영수증 확인과 동시에 실제 분담금만 1회 결제**한다.

> 일행 채팅, 6자리 탑승번호 인증, 24시간 소명, 관리자 심사, 신고·재매칭 차단은 위 3가지 핵심 가치를 안전하게 성립시키기 위한 **지원·예외 처리 기능**이다.

## 2. 3계층 독립 아키텍처 원칙

결제 수단이나 PG 계약 환경이 바뀌더라도 핵심 도메인이 흔들리지 않도록 **3개 독립 계층**으로 설계한다.

```text
[1계층] Matching Engine        — 자동 매칭 (지연 ≤15분, 예상 절약 ≥10%, 동성, 마감 확정)
[2계층] Fare Allocation Engine — 실제 요금 비율 배분, 원 단위 보존, 노쇼 손해 보전 계산
[3계층] Payment & Settlement   — 정산 확인형 후불 간편결제 (확장: 자동결제 / 가승인·매입 / 외부 송금)
```

## 3. 우리가 만드는 것 vs 만들지 않는 것 (프로젝트 경계)

| 구분 | 포함 (확정 범위) | 제외 (범위 밖 / 상용 전환 시 별도 과제) |
|---|---|---|
| **대상·지역** | 대학생(학교 이메일 인증), 대진대학교 및 주변 통학권 | 일반인 대상 상용 운영, 타 지역 현장 좌표 전수 수집 |
| **이동 방식** | **공통 승차 지점 출발** — **하교(학교 → 개별 하차) 중심**, 등교는 지정 거점 → 학교만 보조 지원 | **순차 승차(가는 길에 여러 곳에서 태우기)** |
| **매칭** | 2~4명, 동성, 추가 지연 ≤ 15분, 탑승 전 예상 절약 ≥ 10% (카카오 경로 재검증) | 실시간 차량 위치 추적, 자동 배차·택시 호출 API 연동 |
| **결제·정산** | 결제수단 사전 등록, 영수증 확인 + **실제 요금 비율 후불 1회 결제**(토스 테스트/모의 PG), 정산 3단계 분리(`확정 → 결제 → 모의 지급`) | **적립금/보험 구조(폐지)**, **선결제 부분환불 구조(폐지)**, **실제 계좌 송금(지급대행 계약)** |
| **탑승·노쇼** | 도착 표시 / 결제자 실제 탑승(6자리 탑승번호 5분·5회) / 명시적 운행 시작 / 24시간 소명 / 관리자 심사 / 판단 불가 면책 | GPS 강제 추적 기반 자동 노쇼 처벌, 112 긴급구조 연동 |
| **클라이언트** | 모바일·PC 반응형 웹 (소비자 예약형 UX) | iOS/Android 네이티브 앱 |
| **검증** | 단위·통합·동시성·장애주입·E2E 자동 테스트 + 공개 데이터 모의실험(C7~C16 비교 근거) | 실사용자 상용 운영, 관할기관 인허가·유권해석 |

## 4. 서비스 6단계 핵심 생명주기

```text
[1. 요청] ──▶ [2. 매칭] ──▶ [3. 준비·탑승] ──▶ [4. 운행·요금등록] ──▶ [5. 확인·1회 결제] ──▶ [6. 완료]
 결제수단 확인   조건 검증·일행   도착·탑승번호     택시 운행 후          영수증 확인+1회 결제   모의 지급 기록
 조건·목적지     예상 분담금      인증·운행 시작    실제 요금·영수증       (전원 확인 즉시 /       이용 내역·신고
```

- **채팅**은 2~5단계를 보조하는 독립 메시지함이며, **채팅을 열지 않아도 1~6단계 모든 필수 업무를 완료할 수 있다.**
- **노쇼·취소·승계·이의·미납**은 별도 시스템이 아니라 3~5단계의 **예외 흐름**으로 관리한다.

## 5. 확정된 3대 정산 원칙 및 핵심 업무 규칙 (FR과 분리)

### 3대 정산 원칙
1. **적립금·보험 구조 폐지**: 운영자가 요금 차액을 떠안거나 흑자를 보유하지 않는다(`정상 운행 시 운영자 요금 차액 수지 = 0`).
2. **실제 택시요금 비율 정산**: 인정된 실제 택시요금을 단독 예상 요금 비율로 1원 단위까지 정확히 배분한다(초과 납부자 0명).
3. **정상 이용 시 후불 1회 결제**: 탑승 전 결제 없이 결제수단만 사전 등록하고, 운행 후 영수증 확인과 함께 실제 분담금만 1회 결제한다(부분환불 0건, 추가결제 0건).

### 확정 업무 규칙 요약
| 항목 | 확정 규칙 | 비고 |
|---|---|---|
| **매칭 실행 주기** | 즉시 요청 1분마다, 예약만 있는 회차 5분마다 검사 | `MatchingSettings.everyMinute()` 유지 |
| **확정 시점** | 4명 충족 시 즉시 확정, 2~3명은 모집 마감 시 확정 | `C11` 검증 유지 |
| **매칭 조건** | 동성, 2~4명, 개인 추가 지연 ≤ 15분, **탑승 전 예상 절약 ≥ 10%** | 실제 요금 변동에 따라 실절약률은 달라질 수 있음 |
| **결제수단 사전 등록** | 탑승 요청 전 결제수단(카드/모의 카드) 등록 필수 | 노쇼·미납 진입장벽 |
| **정산 확인 및 결제** | 결제자 영수증 등록 → 동승자 `[확인하고 결제]` 1회 결제. 전원 확인 시 즉시 금액 확정, 무응답 시 **6시간 자동 금액 확정** | 금액 수정 시 정산 버전 증가·이전 확인 무효화 |
| **정산 3단계 상태 분리** | `정산 확정(금액 합의)` → `결제 완료(동승자 수납)` → `지급 완료(결제자 모의 지급)` | 실제 PG 지급은 영업시간·정산 잔액 제약이 별도 존재 |
| **미납 처리** | 결제 기한(확정 후 24시간) 초과 시 **신규 동승 요청 자동 제한** + 관리자 미정산 이관 | 타 일행 전가·운영자 자동 보전 금지 |
| **탑승 인증 (S45)** | 도착 ≠ 실제 탑승 ≠ 운행 시작. 6자리 문자열 5분 기한·5회 제한, 승계 시 이전 번호 무효 | 기존 검증 규칙 유지 |
| **노쇼·판단 불가 보호** | 번호 미입력만으로 노쇼 확정 금지 → 24시간 소명 + 동료 확인 + 관리자 심사. **판단 불가 면책**. 노쇼 확정 시 인정된 실제 손해 증가분만 청구 | 벌금·운영 수익 목적 금지 |
| **예외 요금·보관 기한** | 예상 요금 1.5배 초과/0.5배 미만 시 자동 확정 중단 → 관리자 심사. 영수증·채팅은 종료 후 7일 보관 후 삭제 | `증거 없음` 구분 표시 |

## 7. 공식 용어 사전 (v2.0 통일 기준)

| 공식 용어 | 피해야 할 혼용 표현 | 정확한 의미 |
|---|---|---|
| **탑승 요청** | 매칭 신청, 동승 신청 | 학생이 승차 지점·목적지·출발 조건을 입력해 등록한 매칭 요청 |
| **공통 승차 지점** | 허브, 거점, 앵커 | 일행이 모여 함께 탑승하는 지정 지점 |
| **일행** | 파티, 그룹, 매칭방 | 조건을 통과해 함께 이동하기로 확정된 2~4명의 학생 묶음 |
| **결제자** | 방장, 총무, 대표 결제자 | 마지막에 내리는 학생. 택시를 호출해 실제 택시비를 지불하고 동승자 분담금을 지급받음 |
| **동승자** | 일반 일행원 | 결제자를 제외한 나머지 일행원. 운행 후 영수증을 확인하고 최종 분담금을 1회 결제 |
| **단독 예상 요금** | 혼자 요금, 개인 원가 | 요청 시점에 조회·고정된 혼자 이동 시 예상 요금 (비율 산정 기준) |
| **예상 분담금** | 확정 분담금 *(폐기)* | 일행 예상 요금을 단독 예상 요금 비율로 나눈 탑승 전 참고 금액 |
| **실제 택시요금** | 정산 원금 | 운행 종료 후 영수증으로 확인한 실제 택시비 |
| **최종 분담금** | 확정 금액 | 인정된 실제 택시요금을 단독 예상 요금 비율대로 배분한 최종 부담액 |
| **정산 확정** | 지급 완료 *(혼용 금지)* | 영수증 및 최종 분담금에 대한 확인·심사가 종료되어 금액이 확정된 상태 |
| **결제 완료** | 지급 완료 *(혼용 금지)* | 동승자가 최종 분담금을 결제 완료(수납)한 상태 |
| **모의 지급** | 입금 완료, 송금 완료 | 결제자에게 지급할 금액(`실제 요금 − 본인 최종 분담금`)을 시연 장부에 기록한 상태 (실제 송금 없음) |
| **탑승 미확인** | 노쇼 확정 | 탑승번호 미입력 상태. 24시간 소명 및 관리자 심사 전까지 노쇼가 아님 |
