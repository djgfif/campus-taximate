# 2026-11-19 구현 검증 기록

이 기록은 실행한 검증만 적는다. 현재 작업 트리는 미커밋 상태이며 최종 소스 묶음의 파일별 SHA-256으로 스냅샷을 식별한다. 날짜가 다른 기존 테스트·화면은 오늘의 실행 결과로 세지 않는다.

## 실제 MySQL 업그레이드

- 프로젝트 전용 임시 MySQL 8.0.42, `127.0.0.1:3318` 사용. 기존 MySQL 데이터와 분리했다.
- 빈 `taximate_upgrade` DB에 실제 Flyway V1~V15를 적용했다.
- 기존 회원·READY 파티·도착 표시된 요청을 삽입한 뒤 V16 하나만 추가 적용했다.
- 기존 파티 상태·운행 시작 시각을 보존하고, 기존 도착 표시가 탑승 인증으로 바뀌지 않음을 확인했다.
- `boarding_attempt`의 파티·회원·발급 세대 유일성 제약을 확인했다.
- 반복 마이그레이션은 추가 변경 없이 종료했다.
- V16 단독 업그레이드 결과는 `.cache/mysql-probe/upgrade.log`에 기록했다. V17 추가 후 실제 MySQL에서 신규 V1~V17 설치와 V15→V17 업그레이드를 다시 검증했다.

## 코드 회귀 검증

- Java 21 및 격리 MySQL 8.0.42로 Maven `verify` 통과. 매칭 엔진 73개, 서버 463개. 실패·오류·건너뜀 0개. 로그는 `.cache/verify-final.log`.
- 실제 MySQL을 사용한 결제·탑승 테스트 113개와 인증 동시성, 매칭 확정 경합을 실행했다. 승인 거절 재시도 뒤 `COMPLETED`, 탑승번호 동시 오입력과 세대 변경, 출발 누락의 관리자 복구, 검증 실패 뒤 무료 이탈 환불을 포함한다.
- 프런트 린트·98개 테스트·프로덕션 빌드 통과. 실험 도구 13개 테스트와 세 가지 재현 실행 통과.
- 캐시 단일 회차 768건 중 661건, 캐시 시계열 819건 중 745건, 합성 요청 192건 중 192건 매칭. 세 실행에서 정산 합계 오류 0건. 자료의 성격과 지표 분모는 각 `experiments/reports/` 보고서에 기록했다.

## Chrome 시연

- 새 시연 서버를 사용한 Chrome PC·모바일 크기 E2E 6개 통과. 로그는 `.cache/chrome-final.log`.
- 독립된 결제자·동승자 세션에서 도착, 결제자 번호 공개, 원문 번호 접근 제한, 채팅에서 번호 입력, 명시적 운행 시작, 5분 종료, 영수증과 정산 완료를 확인했다.
- 화면 10장은 `output/playwright/`, 두 흐름의 영상은 발표 폴더의 `시연영상/`에 저장했다. 시연은 모의 결제와 모의 경로로 실행했다.
- 별도 Chrome 시연에서 번호 미수령 소명, 24시간 뒤 관리자 검토, 판단 불가의 `NOT_NO_SHOW` 처리와 감사 기록을 확인했다. `pc-06-admin-review.png`와 `pc-07-admin-audit.png`를 추가로 저장했다. 이 관리자 화면의 콘솔 오류는 0건이었다.

## 제출 묶음

`scripts/release_bundle.py`의 포함·제외 규칙을 검사했다. `.env.example`과 소스는 포함하고 실제 `.env`, 업로드, 원본·비공개 탑승 자료, 빌드 산출물, 의존성 설치 폴더는 제외한다. 생성된 ZIP에는 파일별 해시·현재 HEAD·작업 트리 변경 여부를 기록한다. 최종 검증 후 ZIP을 다시 생성한다.

## 외부 자료 의존성

- 실제 예상 요금과 영수증의 짝 자료는 현재 0건이다. 실제 오차와 실측 기반 민감도는 미검증이다.
- 캐시/가상 요청 실험은 실제 학생 탑승 효과와 구분한다. 이번 실험 도구는 네트워크 호출 경로가 없어 신규 API 호출 0회다.
- 다른 팀원 PC 재현, 11/23 미팅 피드백, 발표 시간 확정과 최종 리허설은 팀의 후속 확인 항목이다.
- 실제 송금·상용 운영 허가·실결제 운영을 검증하지 않는다.
