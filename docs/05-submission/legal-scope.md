# 법적 유효 범위 및 상용 전환 요건 정리 (v2.0)

> **목적:** 현재 시연·모의 검증의 법적 유효 범위와, 상용 서비스 전환 시 별도로 확보해야 할 운송·전자금융·PG·개인정보 요건을 명확히 구분한다.
> **기준일:** 2026-11-25 *(본 문서는 법률 자문·유권해석·관할기관 허가를 대체하지 않는다.)*

---

## 1. 핵심 요약 — 현재 유효 범위 vs 상용 전환 필수 범위

| 구분 | **현재 프로젝트의 법적 유효 범위 (수행·검증 범위)** | **상용 서비스 출시 전 별도 확보 필요 (미확보·범위 밖)** |
|---|---|---|
| **운송·합승** | 학술·캡스톤 목적의 자동 매칭·분담 알고리즘 개발, 모의 시연, 공개 데이터 모의실험 (택시 호출·배차 미수행) | 「택시발전법」 제16조·시행규칙 제11조의2 요건 충족, 「여객자동차 운수사업법」 제49조의18 플랫폼운송중개사업 등록 여부 관할기관 확인 |
| **결제·지급** | 토스페이먼츠 테스트/모의 결제기 시연, 결제자 수령액 **모의 지급 장부 기록 (실제 송금 없음)** | 「전자금융거래법」 제2조·제28조 검토, PG 수납 계약(브랜드페이·티머니모빌리티 등) + 비사업자 개인 지급대행 계약 및 본인·계좌 확인 절차 |
| **수수료·지급 시점** | 모의 환경(수수료·정산 지연 미반영) | PG 결제 수수료(예: ~3%)·지급 건당 비용 부담 주체 확정, PG 정산 잔액 확보 및 영업일 08~15시 지급 요청 제약 대응 |
| **안전·신원** | 학교 이메일 인증, 동성 매칭, 6자리 탑승번호, 회원 신고·재매칭 차단·이용 제한 | 법령상 본인확인(실명/CI) 충족 검증, 112 등 긴급신고 연동, 탑승 가능 좌석 사전 안내 요건 검토 |
| **개인정보·API** | 권한별 최소 접근 제어, 비밀번호 PBKDF2·계좌번호 AES-GCM 암호화, 영수증·채팅 7일 후 삭제 | 「개인정보 보호법」 처리방침·동의·위탁 계약, 위치정보 이용 약관, 카카오·TMAP 상용 약관 및 경로 저장 허용 확인 |

## 2. 관련 법령별 세부 검토 현황

### ① 택시 합승 및 운송 플랫폼 규정
- **근거 법령:** 「택시운송사업의 발전에 관한 법률」 제16조(합승 금지 원칙 및 운송플랫폼 동승 예외, 2022.6.15 시행), 동법 시행규칙 제11조의2, 「여객자동차 운수사업법」 제49조의18(플랫폼운송중개사업 등록)

| 법령상 고려 항목 | 현재 구현 현황 | 상용 전환 시 확인 사항 |
|---|---|---|
| 합승 신청자 본인 확인 | 학교 이메일 코드 인증 구현 | 법령상 본인확인(실명/CI) 요건 충족 여부 확인 필요 |
| 승차 시점·위치 사전 안내 | 승차 지점·출발 시각·경로 사전 표시 | 상용 약관 및 UI 안내 문구 적정성 검토 |
| 탑승 가능 좌석 안내 | 일행 인원(2~4명)·하차 순서 안내 | 차량별 좌석 지정 안내 요건 충족 여부 확인 |
| 경형·소형·중형 택시 동성 합승 | **동성 매칭 필수 적용** | 차종 구분 없이 전 건 동성 매칭 유지 |
| 위험상황 신고 방법 사전 안내 | 앱 내 회원 신고·이용 제한 구현 | **긴급 안전 신고(112 연동 등) 별도 구축 필요** |
| 플랫폼 사업자 등록·면허 | 미확보 (모의 시연 한정) | 택시 배차 없는 사전 동승 매칭의 법 적용 범위 관할기관 확인 필요 |

### ② 전자금융·결제·지급대행 규정 (v2.0 후불 1회 결제 반영)
- **근거 법령:** 「전자금융거래법」 제2조 및 제28조(전자지급결제대행업·선불전자지급수단 발행업 등)
- **v2.0 정산 개편으로 줄어든 규제 부담:**
  - **적립금·가격 보장 폐지:** 운영자가 요금 차액을 보유·보전하는 금융/위험 인수 성격의 논란 제거.
  - **예치금(선불 충전) 미채택:** 선불전자지급수단 발행업 등록 부담 회피.
- **여전히 상용 전 계약·검토가 필요한 영역:**
  - **결제와 지급의 분리:** 동승자 카드 승인 후 PG 매입·정산 잔액이 확보되어야 결제자에게 지급 가능하며, 실제 지급대행 API는 영업일 08~15시 요청 제약이 있다(하교 시간대 17~21시 즉시 계좌 입금 불가).
  - **비정기 후불 결제 계약:** 토스페이먼츠 브랜드페이 또는 티머니모빌리티 PG(모빌리티 비주기 자동결제) 등 실제 PG 심사·계약 및 비사업자 개인 지급 허용 여부 확인이 필요하다.
  - **용어 준수:** 별도 에스크로 계약 없이 일반 PG 결제를 `에스크로`라 부르지 않고, **`결제수단 등록 / 후불 1회 결제 / 모의 지급`** 으로 정확히 표기한다.

### ③ 개인정보 및 외부 API 약관
- 동승자에게 타인의 상세 하차 주소를 숨기고 하차 순서만 표시하며, 영수증 사진·채팅은 종료 후 7일 뒤 자동 삭제한다.
- 상용 전환 시 카카오모빌리티·TMAP 길찾기 응답의 캐시 저장 허용 여부와 개인정보·위치정보 공식 동의 체계를 확보해야 한다.

## 3. 최종 발표용 공식 정리 문장

> “캠퍼스 택시메이트는 대학생 택시 동승 자동 매칭과 단독 예상 요금 비율 기반 실제 요금 정산 절차를 설계·검증하는 캡스톤 프로젝트입니다. 적립금·예치금 같은 운영자 자금 보관 구조를 배제하고 정상 이용 시 후불 1회 결제로 단순화했으며, 현재는 실제 택시 배차와 계좌 송금 없이 모의 결제·모의 지급 장부로 시연합니다. 상용 전환을 위해서는 「택시발전법」·「여객자동차법」상 플랫폼 요건, 긴급신고 등 안전 기준, 비정기 결제·개인 지급대행(PG) 계약과 수수료 구조, 개인정보·지도 API 약관 검토가 별도로 필요합니다.”
