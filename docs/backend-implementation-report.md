# 탑승 인증과 정산 구현 기록

- 공통 승차점 일행에서 호출, 도착, 결제자 실제 탑승 표시, 번호 입력, 명시적 운행 시작을 분리한다. 번호는 현재 결제자에게만 보이며 세대당 5회 실패 제한을 DB에 기록한다. 발급부터 5분 동안 입력 가능하고 승계·취소 시 이전 번호가 무효화된다.
- 마감 뒤 미인증자는 기존 24시간 조사와 소명 절차에 연결한다. 번호 입력 중에도 결제자가 시작할 수 있으며, 인증 창과 조사·이의가 끝난 뒤 정산을 확정한다.
- 결제자가 출발 표시를 누락해도 탑승·운행 증거가 있으면 24시간 뒤 관리자 운행 검토로 넘긴다. 관리자는 운행 여부와 근거를 함께 기록하고, 운행 인정 뒤 영수증을 입력할 수 있도록 복구한다.
- 재결제 후 완료를 막던 확정 거절 승인 이력을 구분한다. 아직 실행해야 할 환불과 추가 결제는 완료 조건에 남긴다.
- 인원 축소는 원래 출발지와 예약 시각으로 최초와 동일한 경로 검증을 사용한다. 경로 실패 시 출발을 잠시 막고 재검증한다. 요청 시각을 보존하며, 무료 이탈과 환불 요청은 같은 트랜잭션에 기록한다.
- 영수증 수정·삭제·관리자 판정은 파티 잠금 아래 조정한다. 운행 검토에는 영수증을 사용할 수 있는지 표시한다.
- Flyway V16은 탑승 증거·번호 세대·시도를 저장한다. V17은 미출발 복구 시각과 재검증 대기를 저장한다. 앞선 마이그레이션은 수정하지 않았다.
